# Эксперимент: прогноз GFS → мощность

Эксперимент завершён: декабрьский порог пройден коррекцией ветра, но январь
показал регрессию. Автоматическое подключение отложено; рабочая модель сохранена.
Подробности и отдельный февральский экспорт — в [результатах](../outputs/gfs_ml/RESULTS.md).

Цель — уменьшить ошибку, возникающую при применении кривой, обученной на
измеренном ветре, к прогнозному ветру GFS. Исходные модели и январские результаты
сохраняются в `outputs/baseline/`.

## Данные

```sh
.venv/bin/python scripts/fetch_noaa.py \
  --start-date 2025-10-30 --end-date 2025-12-30 \
  --workers 16 --output data/weather/noaa_nov_dec.csv
```

62 ежедневных выпуска дают 5 952 погодные строки. Выпуски 30–31 октября нужны
для покрытия первых ноябрьских часов на обоих горизонтах; последний выпуск
содержит также 1 января. Каждый выпуск использует прогноз, опубликованный до
момента расчёта. Фактические будущие ветер и температура не являются входами
модели мощности.

Для первого запуска в ещё не заполненный каталог `outputs/gfs_ml/` выполнить
команду ниже. В репозитории результаты уже сохранены; для повторного запуска
укажите новый каталог, как показано далее.

```sh
.venv/bin/python scripts/evaluate_gfs_ml.py
```

Результаты сохраняются в `outputs/gfs_ml/`: `december/` содержит обучающие пары,
прогнозы всех кандидатов, метрики и модели; `decision.json` — каждый пункт
проверки перед заменой модели; `january_descriptive/` — дополнительную проверку.
При прохождении порога создаётся `deployment/manifest.json` и файлы модели.
Обучение само по себе не включает модель в приложении.

Сохранённый экспериментальный февраль можно пересоздать без изменения рабочей модели:

```sh
.venv/bin/python scripts/replay_february.py \
  --model-manifest outputs/gfs_ml/deployment/manifest.json \
  --output-dir outputs/gfs_ml/february_experimental
```

Повторное обучение откажется перезаписывать каталог с результатами эксперимента,
сохранённым решением или моделью, включая активную. Существующие артефакты
останутся неизменными. Для каждого повторного запуска используйте новую папку:

```sh
.venv/bin/python scripts/evaluate_gfs_ml.py --output-dir outputs/gfs_ml_repeat
```

## Сравнение, зафиксированное до получения результатов

1. Эмпирическая кривая по измерениям до 29 ноября, на входе прогнозный ветер.
2. Линейная коррекция скорости GFS по ноябрьским парам с измеренным ветром,
   затем та же эмпирическая кривая.
3. Прямой CatBoost по прогнозным скорости, температуре, направлению ветра
   (sin/cos), горизонту и местному часу (sin/cos), отдельно для каждой турбины.

Параметры CatBoost: 400 деревьев, глубина 4, learning rate 0.03, L2 10,
RMSE, seed 42. Поиск гиперпараметров не проводится.

Обучающие пары относятся к целевым часам 1–28 ноября. Декабрь используется
для выбора модели. Разбиение идёт по целевому часу: прогнозы одного часа
из разных выпусков не могут оказаться по разные стороны границы. Учёт конца
часового интервала гарантирует, что обучающие метки уже доступны к первому
оцениваемому выпуску.

Для декабря ожидаются 1 480 / 1 468 полных случаев по турбинам: 740 / 734
на каждом горизонте. Все кандидаты оцениваются на одних и тех же строках.

Замена рабочей модели разрешена только при снижении декабрьского RMSE не
менее чем на 5% у каждой турбины, отсутствии ухудшения на обоих горизонтах
у обеих турбин и улучшении в каждой половине декабря (1–15 и 16–31).
Из прошедших кандидатов выбирается наименьший общий RMSE.

## Январь и февраль

Январь уже использовался в предыдущем исследовании. Его результат остаётся
дополнительной описательной проверкой и не участвует в выборе кандидата.
Для этой проверки модели переобучаются строго до 31 декабря 00:00 UTC+5;
используются только выпуски из `noaa_forecasts.csv`, начиная с 31 декабря.
Это сохраняет прежние 1 464 случая на турбину.

Если декабрьский порог пройден, выбранный алгоритм переобучается на доступных
парах ноября–января. Конец любого обучающего часа строго предшествует первому
февральскому выпуску: 31 января, 23:00 UTC+5. Эта версия затем фиксируется
для всего февраля. Подключение выполняется явной записью `active.json` после
проверки сохранённой модели; само наличие экспериментального файла её не включает.

Два месяца — небольшой сезонный пилот. Декабрь является выборкой выбора модели,
а не независимым тестом после выбора. Февральских наблюдений мощности нет;
улучшение февральской ошибки по предоставленным данным проверить невозможно.
Нормированная мощность остаётся в шкале 0–1. Начало часового интервала —
сохранённое допущение исходной задачи; часовой пояс фиксирован UTC+5.
